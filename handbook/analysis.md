**每個人出生後，最早開始做的事情，就是表達。還不會說話時，我們已經會用哭聲、表情與動作表達情感和需求。表達是本能，但讓對方正確理解不是本能。**

**進入社會後，接收資訊的對象更多，彼此的背景、經驗與立場也更加複雜。同一句話，不同的人可能會產生不同理解。**

**職場上的表達必須更加精準，因為別人沒有足夠的時間替我們猜測。除了把事情說出來，更要讓對方理解事件、需求、依據與下一步。**

**這堂課不是重新學習如何說話，而是練習如何讓別人正確理解；我們將學習如何彙整資料、建立故事脈絡並完成邏輯分析，讓表達更清楚、更有效。**

{: .note }
課程目標 協助同仁把零散資訊整理成可理解、可驗證、可溝通並可執行的判斷。

| 課程資料 | 內容 |
|:--|:--|
| 適用對象 | 全體同仁 |
| 課程形式 | 課程講解、案例說明、小組課後作業 |
| 建議時間 | 依部門需求安排，可拆分為五個單元 |
| 版本 | 第26版 |

## 1　課程目的與整體流程

課程目的：協助同仁在進行專案報告或故障分析時，能清楚定義問題、整理零散資訊、進行正反向邏輯分析，最後形成有依據的結論與改善方案，讓聽眾快速理解事件、重點及下一步行動。

| 課程整體流程 |
|:--|
| 定義目標 → 影響評估與緊急應變 → 故事導向 → 邏輯分析 → 邏輯整合 → 清楚報告 |

| 學習單元 | 學習成果 |
|:--|:--|
| 1. 定義目標與資料收集 | 從模糊資料中確認分析邊界，補充有效資料並定義本次分析問題。 |
| 2. 影響評估與緊急應變 | 判斷影響範圍、損失與緊急程度，先控制影響擴大並完成緊急會報。 |
| 3. 故事導向 | 依固定八步驟把事件、影響、應變結果及目前狀態整理成共同故事。 |
| 4. 邏輯分析 | 用正向與反向觀點檢查事實、資料缺口、原因及改善方向。 |
| 5. 邏輯整合 | 將完整故事、證據、原因、方案與驗證整理成一致的報告。 |

## 2　第一單元：定義目標與資料收集

### 2.1 定義目標是一個收斂過程

**定義目標不是直接寫下一句答案，而是把模糊事件逐步轉化成可以分析與改善的問題。**

|  |  |  |  |  |  |  |  |  |
|:--|:--|:--|:--|:--|:--|:--|:--|:--|
| 模糊事件與初步猜測發散 | → | 初步收集資料 | → | 指定分析邊界 | → | 篩選驗證並建立共同條件 | → | 定義問題與改善目標 |

### 2.2 破題：只提供模糊事件

{: .note }
題目 約會遲到。

詢問：所以呢？

第一時間可能出現的回答：

- 吵架了。
- 挨罵了。
- 可能只是單純抱怨。
這些回答都是根據個人經驗補出的初步猜測，題目本身並沒有提供這些結果。

繼續詢問「遲到還可能造成什麼影響？」後，答案會進一步發散：

- 後續行程遞延。
- 餐廳取消訂位。
- 錯過電影開場。
- 趕不上火車或飛機。
- 預約活動超過報到時間。
- 同行者等待並產生不滿。
- 增加改票、交通或重新安排的成本。
{: .note }
觀察重點 答案越分散，越能顯示題目中的資訊不足。每個人都可能用自己的生活經驗補充題目。

### 2.3 發散後辨識資訊缺口

**原題目沒有說明：**

| 缺少條件 | 可能造成的差異 |
|:--|:--|
| 參與人數 | 兩人約會、多人聚會或團體行程的影響不同。 |
| 出遊範圍 | 當地活動、跨縣市或出國行程的風險不同。 |
| 出遊時間 | 短時間用餐、半日活動或多日旅遊的安排不同。 |
| 遲到時間 | 遲到5分鐘與30分鐘可能造成不同結果。 |
| 固定行程 | 是否有訂位、票券、報到期限或交通班次。 |
| 替代方案 | 是否能先報到、改期、通知或由他人代理。 |

{: .note }
學習重點 資訊模糊時產生的不是一個明確問題，而是大量互不一致的問題假設。

### 2.4 初步收集資料並彙整資訊

初步資料收集的目的，是先確認實際發生什麼、造成哪些結果，以及目前有哪些限制；此時先建立事件全貌，不急著決定最後要分析哪一條問題。

| 初步資料 | 需要確認的內容 | 收集目的 |
|:--|:--|:--|
| 人物 | 參與人數、誰遲到、誰已到場。 | 確認事件涉及哪些人。 |
| 時間 | 原定時間、實際時間及偏差多久。 | 確認偏差發生的時間節點。 |
| 原定計畫 | 用餐、電影、交通或其他預定行程。 | 了解原本希望完成什麼。 |
| 限制條件 | 訂位、票券、保留期限、報到時間或交通班次。 | 找出可能產生直接結果的界線。 |
| 實際結果 | 吵架、抱怨、訂位取消、錯過活動或其他已發生結果。 | 分辨猜測與實際發生事項。 |
| 影響與目前狀態 | 後續行程、損失、已採取措施及尚未處理事項。 | 判斷哪一項結果需要優先處理。 |

### 2.5 根據初步資料指定分析邊界

本案例指定問題　餐廳取消訂位，造成後續行程被打亂及原定計畫停擺。

**本次分析範圍　**釐清餐廳訂位被取消的事件與需要改善的結果。吵架、挨罵、單純抱怨及其他行程影響可以保留，但不納入本次分析。

初步資料進來後，先指定本次分析邊界；接著只篩選並驗證與餐廳訂位取消有關的資料。

本案例由課程指定分析對象。實務上選定分析問題時，應確認：有無明確判定條件、能否驗證、是否可控，以及改善後能否追蹤。本案例選擇「訂位被取消」，是因為保留10分鐘是明確界線、取消與報到紀錄可以查證、時間緩衝與報到安排可以控制，且下次預約即可驗證改善結果。

### 2.6 篩選與驗證相關資料

- 這項資料是否會改變我們對問題的判斷？
- 這項資料是否能確認事件發生的時間或節點？
- 這項資料是否能支持或推翻目前的推論？
- 這項資料是否與需要做出的決定有關？
{: .note }
資料篩選範例 這次要確認「訂位為什麼被取消」，因此需要知道訂位時間、餐廳保留期限、實際到達時間，以及是否曾通知餐廳。與取消判定無關的資訊不必蒐集，以免干擾分析重點。

### 2.7 建立共同分析條件

{: .note }
收斂後情境 兩人預約晚上6點用餐，餐廳只保留訂位10分鐘。其中一人遲到30分鐘，另一人也沒有在保留期限內向餐廳報到，導致訂位被取消。

| 條件 | 已知內容 |
|:--|:--|
| 人數 | 2人 |
| 行程範圍 | 當地晚餐 |
| 訂位時間 | 18:00 |
| 保留期限 | 10分鐘 |
| 實際偏差 | 其中一人遲到30分鐘 |
| 另一人報到狀態 | 未在保留期限內先行報到 |
| 已知結果 | 訂位被取消，後續行程中斷。 |
| 後續原定計畫 | 20:00觀看電影。 |
| 緊急應變 | 確認原訂位無法恢復，改訂附近餐廳19:00座位，電影改至21:30。 |
| 應變結果與目前狀態 | 行程已恢復；餐費差額與電影改票費仍待確認。 |
| 補充確認資料 | 原計畫未指定先行報到人員，也未建立延誤通知與替代方案。 |

**建立共同分析條件，是為了讓所有人在相同範圍內完成推導；前面提出的其他可能性仍可保留，但不納入本次分析。**

### 2.8 根據資料明確定義問題與改善目標

| 層次 | 本案例定義 |
|:--|:--|
| 事件／現象 | 其中一人約會遲到30分鐘。 |
| 直接結果 | 超過餐廳保留期限，訂位被取消。 |
| 影響與損失 | 後續行程被打亂，原定計畫停擺。 |
| 本次分析問題 | 固定預約未能在保留期限內完成報到，造成訂位取消並中斷後續行程。 |
| 待確認事項 | 另一人當時是否已到場、是否曾通知餐廳、餐廳是否允許代理報到，以及是否已有替代方案。 |
| 改善目標 | 確保固定預約能在有效期限內完成報到；發生延誤時能及時啟動替代方案，避免單一延誤使整體行程停擺。 |

問題邊界確認後，還要繼續檢查造成事件的條件與流程缺口。本節的目的不是擴大題目，而是在既定範圍內找出需要驗證的深層問題。

### 2.9 問題背後的問題

- 集合時間是否沒有預留緩衝？
- 是否未確認餐廳保留規則？
- 發現延誤後是否曾通知？若未通知，原因是什麼？
- 為何不能由另一人先完成報到？
- 是否缺少延誤時的替代方案？

### 2.10 必須分清楚的概念

- 事件不等於問題。
- 影響不等於改善目標，但能幫助我們找到需要維持的結果。
- 蒐集資料不是越多越好，而是要與判斷有關。
- 條件未明確前，不要急著提出原因或改善方案。
- 問題定義清楚後，才進入流程分析與邏輯推導。
- 問題不等於原因：問題是要改善的狀態，原因是造成該狀態的機制。
{: .note }
本單元結論 模糊資訊會使問題發散；補充並篩選有效資訊後，才能界定問題範圍，找出本次需要改善的問題與期望結果。

## 3　第二單元：影響評估與緊急應變

### 3.1 從生活案例轉換到工作情境

約會遲到案例不是在檢討生活習慣，而是用熟悉的情境練習辨識事件如何逐步擴大，並將同一套思考方式轉換到工作現場。

| 生活案例 | 工作情境 | 對應意義 |
|:--|:--|:--|
| 約會遲到 | 訂單未按時完成／遲交 | 原定時間節點發生延誤 |
| 餐廳取消訂位 | 預約貨運逾時離開 | 錯過無法等待的關鍵節點 |
| 後續行程被打亂 | 後續交期或生產排程受影響 | 單一延誤向後擴散 |
| 後續行程無法繼續 | 交期無法達成，面臨客戶索賠或合約解約 | 延誤擴大為重大營運與合約風險 |

工作情境影響鏈　訂單未按時完成 → 預約貨運逾時離開 → 後續交期或生產排程受影響 → 交期無法達成，面臨客戶索賠或合約解約

### 3.2 問題處理的優先原則

發生問題時，不能只急著尋找原因。應先確認後續影響是否會繼續擴大；如果可能造成重大損失，先採取緊急應變措施控制影響，再進入原因分析與長期改善。

|  |  |  |  |  |  |  |  |  |
|:--|:--|:--|:--|:--|:--|:--|:--|:--|
| 事件發生 | → | 確認後續影響 | → | 判斷緊急程度 | → | 採取應變措施 | → | 原因分析與改善 |

| 處理階段 | 需要確認的問題 | 目的 |
|:--|:--|:--|
| 影響評估 | 影響哪些人、流程、交期或合約？範圍多大？多久後擴大？ | 確認處理優先順序 |
| 緊急應變 | 現在能做什麼，先阻止影響繼續擴大？ | 維持流程並降低損失 |
| 原因分析 | 事件為什麼發生？哪些是事實、推論與待確認事項？ | 找出直接原因與促成條件 |
| 改善與驗證 | 如何避免再次發生？如何確認措施有效？ | 建立長期改善與追蹤 |

**重要原則　**緊急應變是先控制影響，不代表原因已經確認；應變完成後仍須繼續蒐集資料、分析原因並驗證改善效果。

### 3.3 緊急會報優先收集資料

緊急會報不必等待完整原因分析，應先收集足以判斷影響、損失、處理時限及所需資源的資料，讓相關人員可以立即決策。

| 優先資料 | 需要確認的內容 | 會報用途 |
|:--|:--|:--|
| 原定計畫內容 | 原定目標、時程、交期、工作節點及預期結果。 | 確認原本應完成什麼 |
| 目前異常狀態 | 目前停在哪個節點、實際偏差、剩餘處理時間。 | 判斷緊急程度 |
| 計畫影響範圍 | 影響哪些人員、部門、流程、交期、客戶或合約。 | 判斷影響是否持續擴大 |
| 已造成或預估損失 | 時間、產能、交期、營收、客戶及商譽損失。 | 判斷事件嚴重程度 |
| 後續補救措施 | 目前已採取、可立即採取及備選的應變措施。 | 控制影響並恢復流程 |
| 額外產生費用 | 加急運費、加班、重工、替代方案、賠償或其他費用。 | 評估應變成本 |
| 需要的決策或支援 | 需要誰核准、協調哪些部門、投入哪些人力或資源。 | 加快決策與執行 |

**會報原則　**已確認資料、預估資料及未知事項必須分開標示；緊急不代表可以把推測當成事實。

## 4　第三單元：故事導向

**單元目的：把前一單元收集到的零散資訊重新排列，形成其他人看得懂、能轉述，也能繼續分析的完整故事。**

{: .note }
核心觀念 故事導向不是把內容講得精彩，而是依共同順序把事情講清楚。

### 4.1 為什麼需要故事導向

- 零散資料通常來自不同時間、人物及來源，直接堆在一起會讓人抓不到重點。
- 如果資訊沒有順序，聽者容易自行補充假設，重新造成問題發散。
- 整理成故事後，所有人才能對事件經過、影響與問題形成共同理解。
- 共同理解建立後，才適合進入正反向意見與邏輯整合。

### 4.2 故事的基本結構

| 故事八步驟 |
|:--|
| 1 背景與人物 → 2 原定目標 → 3 關鍵節點 → 4 實際事件 → 5 影響與損失 → 6 緊急應變 → 7 應變結果與目前狀態 → 8 待處理問題 |

| 故事步驟 | 需要回答的問題 | 注意事項 |
|:--|:--|:--|
| 1. 背景與人物 | 誰參與？事情發生在哪裡、何時？ | 只保留與問題有關的背景。 |
| 2. 原定目標 | 原本希望完成什麼結果？ | 先說原定狀態，才能看出偏差。 |
| 3. 關鍵節點 | 有哪些時間點、動作或限制？ | 依時間或因果順序排列。 |
| 4. 實際事件 | 哪個節點發生什麼偏差？ | 描述事實，不先貼標籤。 |
| 5. 影響與損失 | 偏差造成哪些範圍與損失？ | 區分直接結果與擴大影響。 |
| 6. 緊急應變 | 當時先做了什麼，阻止影響擴大？ | 記錄時間、措施及負責人。 |
| 7. 應變結果與目前狀態 | 措施結果如何？目前還有哪些風險？ | 區分已恢復與尚未處理事項。 |
| 8. 待處理問題 | 接下來需要分析、改善或決定什麼？ | 讓聽者知道報告與會議目的。 |

### 4.3 從零散資訊整理成故事

{: .note }
零散資訊 兩人、18:00訂位、保留10分鐘、一人晚到30分鐘、另一人未報到、訂位取消、20:00電影、原訂位無法恢復、改訂19:00附近餐廳、電影改至21:30、行程恢復、額外費用待確認。

**如果只把上述資訊逐項念出，聽者仍需要自己判斷先後關係。整理後的故事應該是：**

{: .note }
整理後故事 兩人原本預約18:00到餐廳用餐，並安排20:00觀看電影；餐廳只保留訂位10分鐘。其中一人晚到30分鐘，另一人也未在18:10前向餐廳報到，訂位因此被取消，後續行程被打亂。兩人立即聯絡原餐廳，確認訂位無法恢復，改訂附近餐廳19:00的座位，並將電影改至21:30場次。目前行程已恢復，但餐費差額與電影改票費仍待確認；後續需要分析為何沒有在期限內完成報到，以及如何避免單一延誤再次中斷整體行程。

### 4.4 故事整理的三項規則

| 規則 | 說明 | 本案例示例 |
|:--|:--|:--|
| 依順序排列 | 依時間、流程或因果關係安排資訊。 | 依序說明原定計畫、逾時取消、影響與損失、緊急應變、應變結果、目前狀態及待處理問題。 |
| 只使用已確認資訊 | 未確認的內容要標示為假設，不可直接寫成事實。 | 不知道遲到原因時，不可直接寫成『因為沒有時間觀念』。 |
| 保留主線需要的內容 | 與目標無關的細節先移除，避免故事失焦。 | 餐廳種類或穿著通常不影響訂位取消的判斷。 |

### 4.5 事實、推論與假設

| 資訊類型 | 定義 | 例子 |
|:--|:--|:--|
| 事實 | 可以由紀錄、觀察或共同確認支持。 | 訂位18:00、保留10分鐘、實際晚到30分鐘。 |
| 推論 | 根據事實形成的合理解釋。 | 未在保留期限內報到，因此訂位被取消。 |
| 假設 | 尚未取得證據，但可能需要驗證。 | 遲到可能與交通、出門時間或資訊理解有關。 |

### 4.6 故事是否整理完成

- □ 沒有接觸原始資料的人，也能說出事件發生的順序。
- □ 聽者能分辨原定目標、實際事件及造成的影響。
- □ 故事沒有把未確認的原因寫成事實。
- □ 每一段資訊都與目前要分析的問題有關。
- □ 聽者可以根據故事繼續提出正反向意見或需要補充的資料。
- □ 故事已說明緊急應變措施、執行結果及目前狀態。
- □ 聽者能立即知道尚未排除的影響，以及本次需要分析或決策的事項。
{: .note }
本單元結論 資料蒐集完成後，必須透過順序、因果與重點篩選，把零散資訊轉化成共同故事；別人看得懂，團隊才有辦法討論同一個問題。

## 5　第四單元：邏輯分析

**單元目的：從正向與反向兩個角度檢查問題認知、原因與改善方案，並練習在會議中面對疑問時，以資料回應、修正或補充。**

{: .note }
核心觀念 正反向思考不是為了爭論，而是降低盲點，找出更接近真實的原因與更有效的改善方案。

### 5.1 邏輯分析的兩個方向

| 分析方向 | 主要目的 | 需要回答的問題 |
|:--|:--|:--|
| 正向分析 | 整理自己的問題認知、改善方向與目標。 | 我認為問題是什麼？依據是什麼？想改善到什麼狀態？ |
| 反向分析 | 預想他人在會議中可能提出的疑問、反例與替代原因。 | 別人可能質疑什麼？哪些證據不足？還有其他合理解釋嗎？ |

### 5.2 正向分析：確認自己的認知

- 用一句話說明目前定義的問題。
- 列出支持此問題定義的事實與資料。
- 說明問題造成的直接影響與需要維持的結果。
- 提出目前認為需要改善的方向及目標。
- 標示哪些內容仍是推論或尚待驗證的假設。
{: .note }
本案例正向觀點 固定預約未在保留期限內完成報到，造成訂位取消及後續行程中斷。已知報到狀態，但另一人到場時間與通知紀錄仍需確認；改善方向須待原因證據完成後確定。

### 5.3 反向分析：預想會議中的疑問

| 可能疑問 | 需要準備的回應資料 |
|:--|:--|
| 訂位真的是因遲到被取消嗎？ | 餐廳保留規則、到達時間及取消紀錄。 |
| 另一人當時是否已到場？若已到場，為何沒有先報到？ | 餐廳報到規則、訂位人資料及當時處理經過。 |
| 是否已經通知餐廳？ | 通話、訊息或平台聯絡紀錄。 |
| 問題是個人遲到，還是流程沒有備案？ | 集合安排、時間緩衝及替代方案。 |
| 提出的改善方法真的能避免再次發生嗎？ | 改善措施與失敗原因之間的對應關係。 |

### 5.4 面對疑問的回應步驟

|  |  |  |  |  |  |  |  |  |
|:--|:--|:--|:--|:--|:--|:--|:--|:--|
| 確認問題 | → | 區分事實與假設 | → | 提供證據 | → | 承認缺口 | → | 修正或追蹤 |

- 先重述對方疑問，確認自己沒有誤解。
- 回答時先說已確認事實，再說推論與尚待確認內容。
- 有證據就提供來源；沒有證據時，不用猜測硬答。
- 若疑問成立，修正原本判斷不是失敗，而是分析變得更完整。
- 無法當場確認的問題，記錄需要補充的資料、責任人與期限。

### 5.5 不為爭論而爭論

| 不建議做法 | 建議做法 |
|:--|:--|
| 為了保住原結論而忽略新證據。 | 只要新證據成立，就調整問題定義或改善方案。 |
| 把不同意見視為針對個人。 | 把疑問轉換成需要驗證的資料或條件。 |
| 沒有資料仍反覆主張自己的看法。 | 清楚說明資料缺口，安排後續確認。 |
| 討論停留在誰對誰錯。 | 回到真實原因、影響及改善是否有效。 |

### 5.6 邏輯分析完成條件

- □ 問題認知與改善目標有資料支持。
- □ 已列出會議中可能出現的重要疑問。
- □ 已準備支持、推翻或修正結論所需的證據。
- □ 能清楚說明哪些內容仍不確定。
- □ 改善方案直接對應真實原因，而不是只處理表面現象。
- □ 討論最後能形成下一步，而不是停留在立場爭論。
{: .note }
本單元結論 正向分析讓自己先把問題與目標說清楚；反向分析讓方案經得起他人的疑問。兩者結合，目的都是更接近真實原因並形成有效改善。

## 6　第五單元：邏輯整合

**單元目的：將問題定義、事件故事及正反向分析整合成一份有結論、有依據、有行動並可追蹤的專案報告或故障分析。**

{: .note }
核心觀念 邏輯整合不是把資料全部放進報告，而是讓每一項證據都能支持結論，每一項改善都能對應原因。

### 6.1 整合輸入與輸出

| 來源單元 | 提供的內容 | 整合後用途 |
|:--|:--|:--|
| 定義目標 | 分析邊界、有效資料、本次分析問題與改善目標 | 確認報告要回答的核心問題。 |
| 影響評估與緊急應變 | 影響與損失、應變措施、應變結果及目前狀態 | 先說明風險是否受控及目前停在哪裡。 |
| 故事導向 | 統一八步驟事件故事 | 讓聽眾理解事情如何發生及處理。 |
| 邏輯分析 | 正向認知、反向疑問、證據與資料缺口 | 檢查原因與方案是否站得住腳。 |
| 邏輯整合 | 統一十段報告、責任、期限與驗證 | 形成可以決策及執行的報告。 |

### 6.2 報告整合順序

| 順序 | 報告段落 |
|:--|:--|
| 1 | 報告目的 |
| 2 | 原定計畫 |
| 3 | 事件經過 |
| 4 | 影響與損失 |
| 5 | 緊急應變 |
| 6 | 應變結果與目前狀態 |
| 7 | 資料與證據 |
| 8 | 邏輯分析與原因判定 |
| 9 | 改善方案 |
| 10 | 執行追蹤 |

- 第1段先說明這次要決定或改善什麼，不要把結論留到最後。
- 第2至3段用原定計畫與事件經過交代事情如何發生。
- 第4至6段說明影響與損失、已採取的應變措施及目前狀態。
- 第7段列出支持結論的事實、反向疑問及仍待確認內容。
- 第8至10段的原因必須由證據推導，改善措施逐項對應原因，並指定責任人、期限與驗證方式。

#### 6.2.1 讓會議人員快速進入狀態

緊急會報收集的資料應直接帶入後續正式報告。報告開場先把事件故事交代完整，與會人員才能快速理解原由、目前風險及需要決策的重點。

快速進入狀態原則　十段架構中的前六段，先交代報告目的、原定計畫、事件、影響、緊急應變及目前狀態；與會人員掌握背景後，再進入證據、原因、改善與追蹤。

### 6.3 專案報告／故障分析共用架構

| 報告段落 | 需要回答的問題 |
|:--|:--|
| 1. 報告目的 | 這次要分析、改善或決定什麼？ |
| 2. 原定計畫 | 原定目標、時程、交期及預期結果是什麼？ |
| 3. 事件經過 | 事件依時間與關鍵節點如何發展？ |
| 4. 影響與損失 | 影響哪些人、流程、交期、成本或結果？ |
| 5. 緊急應變 | 為避免影響擴大，立即採取了什麼措施？ |
| 6. 應變結果與目前狀態 | 措施結果如何？目前還有哪些影響或風險？ |
| 7. 資料與證據 | 有哪些已確認事實？資料來源是否可靠？ |
| 8. 邏輯分析與原因判定 | 問題、直接原因、促成條件與系統性問題如何由證據推導？ |
| 9. 改善方案 | 採取哪些矯正、預防或替代措施？ |
| 10. 執行追蹤 | 責任人、期限、驗證指標及結果為何？ |

### 6.4 整合檢查

- □ 報告結論能回應最初定義的目標。
- □ 故事脈絡足以讓未參與事件的人理解。
- □ 事實、推論及假設已明確區分。
- □ 重要疑問已經回答，未確認事項已有追蹤安排。
- □ 原因與改善措施有直接對應關係。
- □ 聽眾看完後知道要做什麼、由誰做及如何確認。

## 7　完整示範案例：約會遲到

示範目的：依五個單元的順序，從一個模糊事件逐步形成可以報告、檢討及執行的完整分析。每一階段均標示對應章節與輸出。

{: .note }
初始題目 約會遲到。

### 7.1 案例起點：模糊事件與資訊發散

第一次詢問：所以呢？

同仁可能先回答：

- 吵架了。
- 挨罵了。
- 可能只是單純抱怨。
這些內容目前都只是初步猜測，不能直接當成事件結果。

繼續詢問可能造成的影響：

- 餐廳取消訂位。
- 錯過電影開場。
- 趕不上火車或飛機。
- 後續行程遞延或取消。
- 同行者等待並產生不滿。
- 增加改票、交通或重新安排的成本。
{: .note }
分析重點 題目沒有提供足夠條件，每個人會用自己的經驗補充情境，因此答案會大量發散。

### 7.2 第一步：定義目標與資料收集

| 欄位 | 內容 |
|:--|:--|
| 對應章節 | 第2章｜第一單元：定義目標與資料收集 |
| 目前輸入 | 約會遲到；其他條件尚未說明。 |
| 思考問題 | 缺少哪些條件？哪些資料會影響判斷？本次需要改善的是什麼？ |
| 使用方法 | 辨識資訊缺口 → 初步收集資料 → 指定分析邊界 → 篩選與驗證 → 建立共同條件 → 定義問題與目標 |
| 本步驟輸出 | 完成初步資料表、指定分析邊界，並建立共同的問題範圍與改善目標。 |

#### 初步收集資料

| 條件 | 指定內容 |
|:--|:--|
| 人數 | 2人 |
| 行程範圍 | 當地晚餐 |
| 訂位時間 | 18:00 |
| 餐廳規則 | 只保留訂位10分鐘 |
| 實際事件 | 其中一人晚到30分鐘 |
| 另一人報到狀態 | 未在保留期限內向餐廳報到 |
| 已知結果 | 訂位被取消，後續行程中斷。 |
| 後續原定計畫 | 20:00觀看電影。 |
| 緊急應變 | 確認原訂位無法恢復，改訂附近餐廳19:00座位，電影改至21:30。 |
| 應變結果與目前狀態 | 行程已恢復；餐費差額與電影改票費仍待確認。 |
| 補充確認資料 | 原計畫未指定先行報到人員，也未建立延誤通知與替代方案。 |

**根據初步資料指定分析邊界**

本案例指定問題　餐廳取消訂位，造成後續行程被打亂及原定計畫停擺。

本次不分析吵架、挨罵或單純抱怨，而是從餐廳取消訂位開始確認需要補充的資料與改善目標。

{: .note }
問題定義 固定預約未能在保留期限內完成報到，造成訂位取消並中斷後續行程。

{: .note }
改善目標 確保固定預約在期限內完成報到；延誤時先控制影響，再依確認原因建立緩衝、通知與替代機制。

### 7.3 第二步：影響評估與緊急應變

先確認訂位取消是否會使後續行程繼續擴大，再採取應變措施恢復行程；應變完成後才進入完整故事與原因分析。

| 對應章節 | 第3章｜第二單元：影響評估與緊急應變 |
|:--|:--|
| 影響判斷 | 訂位取消將使20:00電影行程無法銜接，整體計畫有停擺風險。 |
| 緊急應變 | 確認原訂位無法恢復後，改訂19:00附近餐廳，電影改至21:30。 |
| 應變結果 | 行程恢復；餐費差額及電影改票費待確認。 |
| 本步驟輸出 | 已控制擴大影響，並取得後續故事與報告需要的應變資料。 |

### 7.4 第三步：故事導向

| 欄位 | 內容 |
|:--|:--|
| 對應章節 | 第4章｜第三單元：故事導向 |
| 目前輸入 | 已確認人物、時間、規則、事件、影響、緊急應變、應變結果及目前狀態。 |
| 思考問題 | 如何依順序讓未參與事件的人看懂？哪些細節與主線有關？ |
| 使用方法 | 背景與人物 → 原定目標 → 關鍵節點 → 實際事件 → 影響與損失 → 緊急應變 → 應變結果與目前狀態 → 待處理問題 |
| 本步驟輸出 | 一段依統一八步驟整理、可理解、可轉述且未加入假設的事件故事。 |

{: .note }
整理後故事 兩人原本預約18:00到餐廳用餐，並安排20:00觀看電影；餐廳只保留訂位10分鐘。其中一人晚到30分鐘，另一人也未在18:10前向餐廳報到，訂位因此被取消，後續行程被打亂。兩人立即聯絡原餐廳，確認訂位無法恢復，改訂附近餐廳19:00的座位，並將電影改至21:30場次。目前行程已恢復，但餐費差額與電影改票費仍待確認；後續需要分析為何沒有在期限內完成報到，以及如何避免單一延誤再次中斷整體行程。

### 7.5 第四步：邏輯分析

| 欄位 | 內容 |
|:--|:--|
| 對應章節 | 第5章｜第四單元：邏輯分析 |
| 目前輸入 | 已形成共同故事與初步問題定義。 |
| 思考問題 | 目前認知有何依據？會議中可能被質疑什麼？還有其他合理解釋嗎？ |
| 使用方法 | 正向分析 → 反向分析 → 準備證據 → 確認缺口 → 修正認知 |
| 本步驟輸出 | 經過疑問檢查的問題認知、原因假設與改善方向。 |

#### 正向分析

| 項目 | 分析內容 |
|:--|:--|
| 目前認知 | 固定預約未在保留期限內完成報到，造成訂位取消並中斷後續行程。 |
| 支持事實 | 18:00訂位、保留10分鐘、一人晚到30分鐘、另一人未在期限內向餐廳報到、訂位取消及後續行程中斷。 |
| 改善方向 | 先恢復行程，再針對報到責任、時間緩衝、延誤通知及替代方案提出改善。 |
| 資料缺口 | 另一人當時是否已到場、餐廳是否允許代理報到，以及通知紀錄。報到狀態已知，到場狀態未知。 |

#### 反向分析與回應

| 會議可能疑問 | 回應方式 |
|:--|:--|
| 訂位真的是因遲到被取消嗎？ | 確認餐廳保留規則與取消紀錄；未確認前標示為待驗證。 |
| 另一人當時是否已到場？若已到場，為何沒有先報到？ | 分別確認到場時間、報到紀錄、訂位人資料及餐廳代理報到規則。 |
| 通知餐廳是否能保留訂位？ | 查詢餐廳規則，不能直接假設一定有效。 |
| 問題是個人遲到還是沒有備案？ | 兩者可能同時存在，須分開判定直接原因與系統性條件。 |
| 改善方案能否避免再次取消？ | 逐項確認措施是否對應失敗節點，並安排後續驗證。 |

{: .note }
分析原則 不同意見不是要贏得爭論，而是把尚未確認的假設轉換成需要蒐集的資料。

### 7.6 第五步：邏輯整合

| 欄位 | 內容 |
|:--|:--|
| 對應章節 | 第6章｜第五單元：邏輯整合 |
| 目前輸入 | 問題、故事、事實、疑問、原因假設及改善方向。 |
| 思考問題 | 結論是否有證據？原因與改善是否對應？聽眾是否知道下一步？ |
| 使用方法 | 依統一十段報告架構整理。 |
| 本步驟輸出 | 一份可以報告、決策、執行及追蹤的完整案例。 |

#### 原因整合

| 原因層次 | 本案例暫定判斷 | 確認狀態 |
|:--|:--|:--|
| 直接原因 | 18:10保留期限屆滿時，沒有任何人完成餐廳報到，觸發取消規則。 | 已確認（訂位時間與取消紀錄） |
| 促成條件 | 一人晚到30分鐘；事前未指定誰負責先行報到。 | 已確認（晚到時間與行程分工資料） |
| 待確認事項 | 另一人當時是否已到場，以及延誤發生時是否曾通知餐廳。 | 待取得到場時間與通知紀錄 |
| 系統性問題 | 行程缺少時間緩衝、延誤通知規則及替代方案，單一延誤因而擴大成整體行程中斷。 | 由事件資料推論，需驗證 |

{: .note }
問題與原因的區別 2.7 的「本次分析問題」說的是要改善的狀態（固定預約未在保留期限內完成報到）；原因說的是造成該狀態的機制（未指定報到責任、缺少時間緩衝與延誤通知規則）。兩者若用同一句話帶過，原因判定等於沒有推導。

#### 改善與驗證

| 改善措施 | 對應問題 | 驗證方式 |
|:--|:--|:--|
| 集合時間早於訂位時間，保留交通及報到緩衝。 | 缺少時間緩衝。 | 確認未來固定預約是否依緩衝時間安排。 |
| 預約前確認保留期限及報到規則。 | 不了解限制條件。 | 將規則記錄於行程資訊。 |
| 預估延誤時立即通知同行者與餐廳。 | 缺少延誤通知規則。 | 確認通知時間及餐廳回覆。 |
| 指定先行報到負責人；準備鄰近替代方案。 | 未指定報到責任，且缺少替代方案。 | 下次行程前完成責任與備案確認。 |

### 7.7 完整報告

| 報告段落 | 案例內容 |
|:--|:--|
| 1. 報告目的 | 分析固定預約為何失敗，避免單一延誤再次中斷整體行程。 |
| 2. 原定計畫 | 18:00餐廳訂位、保留10分鐘，原定20:00觀看電影。 |
| 3. 事件經過 | 一人晚到30分鐘，另一人未在18:10前報到，餐廳依規定取消訂位。 |
| 4. 影響與損失 | 用餐與電影行程被打亂，並產生餐費差額及電影改票費。 |
| 5. 緊急應變 | 立即聯絡原餐廳；確認無法恢復後，改訂附近餐廳並調整電影場次。 |
| 6. 應變結果與目前狀態 | 改訂19:00餐廳、電影改至21:30，行程已恢復；額外費用仍待確認。 |
| 7. 資料與證據 | 訂位時間、保留規則、到達與報到紀錄、餐廳回覆、改訂及改票紀錄。 |
| 8. 邏輯分析與原因判定 | 取消規則由逾時未報到觸發；促成條件是未指定報到責任，系統性問題是缺少緩衝、通知規則及替代方案。 |
| 9. 改善方案 | 預留時間緩衝、指定報到負責人、建立延誤通知規則並準備替代方案。 |
| 10. 執行追蹤 | 行程建立人於預約時記錄規則與備案；參與人於出發前確認分工；下次預約後檢查是否依流程執行。 |

{: .note }
示範結論 案例的價值不在餐廳或約會本身，而在示範如何把模糊事件依固定流程轉化成一份條理清楚、能回應疑問並可執行的分析報告。
